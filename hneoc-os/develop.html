开发与调试

写程序、回归测试、串口日志

想在 HNeoC-OS 上写自己的程序，或者改完内核想确认"没弄坏别的"？看这一页。

在宿主机开发用户程序

在 user/ 目录下新建 .c 文件即可，下次 .\build.ps1 会自动编译成 fsroot/<名字>.lxe 并打包进磁盘镜像，敲名字就能跑——不需要注册任何命令表。

// user/hello.c
#include "hneoc.h"

static int counter[8];      // 放在 .bss，加载器会清零

int main(void) {
    puts("hello from ring 3, pid ");
    put_int(getpid());
    putchar('\n');
    return 0;
}

写程序优先用 user/lib/ 那套标准命名的用户态 C 库（string.h stdio.h stdlib.h unistd.h term.h……），#include "hneoc.h" 一次全拉进来。其中 term.h 把 ANSI 转义序列整个包住，写全屏程序时全程不出现一个 "\x1b["。

⚠️ 两个硬性要求：入口函数必须叫 main；用户程序里不要出现排在代码前面的静态初始化逻辑——LXE 入口偏移固定为 0。

一条命令的全系统回归

改完东西想确认"没弄坏别的"：

.\tools\regress.ps1                 # 构建 + 启动 + 跑全部检查（三十多项）
.\tools\regress.ps1 -SkipBuild      # 用当前镜像，省掉构建
.\tools\regress.ps1 -Only hpm       # 只跑名字匹配的检查
.\tools\regress.ps1 -List           # 列出所有检查
.\tools\regress.ps1 -KeepRunning    # 跑完不关机，自己接着玩

它把"构建 → 无头启动 → 敲命令 → 对着串口日志断言"固化成脚本：每个检查发完命令后轮询串口日志直到期望的正则全部出现（不用固定 sleep），虚拟机崩了会立刻停下并指出是哪个检查。新加功能时顺手往检查表里加一条，比手敲一遍可靠得多。

串口日志（强烈推荐）

内核把屏幕字符同时写到 COM1。run.ps1 已自动把串口重定向到 build/serial.log，宿主机直接读文件就能看到和屏幕完全一致的文本，不用截图。

自动化输入与内存转储

.\tools\vm-type.ps1 -VmName "HNeoC" -Text "taskmgr" -Enter
.\tools\vm-type.ps1 -VmName "HNeoC" -Key Up
& "D:\VB\VBoxManage.exe" debugvm "HNeoC" dumpvmcore --filename build\vmcore.elf

把 guest 写出来的文件挖出来看

调试 hncc 产物这类"系统里的程序产生的东西"时，光看屏幕输出不够，要拿到文件本体：关机后把 VDI 转成裸镜像，按 HNeoFS 目录表（LBA 2049 起，每项 64 字节）找到文件，再反汇编：

.\run.ps1 -Stop
& "D:\VB\VBoxManage.exe" clonemedium build\hneoc-os.vdi build\guest-dump.img --format RAW
& "D:\mingw32\bin\objdump.exe" -b binary -m i386 -M intel `
    --adjust-vma=0x40000000 -D build\out.bin

用户程序都加载到 0x40000000，所以 --adjust-vma 用这个基址；40 字节的 LXE 头部要跳过。hncc 的两个代码生成 bug 就是这么定位的。
